1. What is Jackdaw?

Jackdaw is an open-source Python reimplementation of Balatro — a poker-based roguelike card game. It runs entirely headless (no graphics, no game window) and is designed for reinforcement learning research: you can simulate thousands of games per minute and train neural network agents against it.

🃏

Game engine

Full Balatro rules: hands, jokers, consumables, shop, blinds, scoring — all in Python.

🤖

RL environment

Wraps the engine as a Gymnasium env so you can train PPO, DQN, or any SB3 algorithm.

👁️

Visualization (new)

What we added: a live terminal display and browser dashboard to watch or play any game.

Before our changes, you could only run the engine programmatically — there was no way to actually see what was happening. Every game was just numbers in memory.

2. What we built

Two simultaneous outputs

Every game step broadcasts to two places at the same time:

💻

Rich terminal display

Colored panels directly in PowerShell. Cards with suit symbols, score progress bar, phase info, action log.

🌐

Browser dashboard

Live web UI at http://127.0.0.1:8765. Auto-opens when you run the game. Real-time updates via WebSocket.

Two game modes

👁️

Watch mode

An AI agent (random, greedy, or trained PPO) plays automatically. You observe every decision in real time.

▶️

Play mode

You control every action via the browser. Click cards to select them, click buttons to play, discard, buy, etc.

PPO agent integration

We wired a trained MaskablePPO model into the watch mode so you can visually see what a neural network agent does when it plays Balatro. Train for hours, then watch it play through the dashboard.

4. How it works

The data flow

Game engine step()
→
observer.emit()
→
RichRenderer
+
WebServer queue
→
Browser via WebSocket

After every single game action, observer.emit() is called. It serializes the entire game state (cards in hand, jokers, score, legal actions, history) to a Python dict, then hands it to the terminal renderer and drops it into a thread-safe queue for the web server to broadcast.

The two servers

The browser dashboard runs two independent servers in background threads:

Server Port What it does
HTTP 8765 Serves index.html, style.css, app.js to the browser
WebSocket 8766 Pushes live game state to the browser every ~40ms. Also receives actions in play mode.

They are on separate ports because using a single server for both HTTP and WebSocket caused routing conflicts in every version of FastAPI/Starlette we tried. Two separate servers (Python's built-in http.server + websockets library) is simpler and fully reliable.

Watch mode internals

The observer runs the full game loop itself, calling agent(gs, legal_actions) at every step, then sleeping for --speed seconds so you can follow along. After game over it keeps the servers alive until you press Ctrl+C.

Play mode internals

The game loop blocks on a thread-safe queue (action_queue.get()). The browser sends a JSON action over WebSocket when you click a button. The server puts it in the queue. The blocked game loop wakes up, deserializes the action, executes it, and sends the new state back.

PPO agent internals

To use a trained PPO model in watch mode we had to bridge two different interfaces. The model was trained with Gymnasium's observation/action encoding. The observer expects a simple (gs, legal_actions) → action function. The bridge (ppo_agent.py) does:

  1. Encode the raw game state dict into numpy arrays using the same encode_observation() function used during training
  2. Build the action table and boolean mask using get_action_mask()
  3. Call model.predict(obs, action_masks=mask)
  4. Convert the integer output back to an engine Action using factored_to_engine_action()

5. Installation

Requirement: Python 3.12 or newer. Check with python --version.

Install the project and visualization dependencies

Run this once from the jackdaw/ folder:

pip install -e ".[viz]"

The [viz] extra installs: rich, fastapi, uvicorn, websockets on top of the base engine dependencies.

Install training dependencies (optional — only for PPO)

pip install tensorboard sb3-contrib stable-baselines3

Verify installation

jackdaw --help

You should see two subcommands: validate and run.

6. How to run

Watch mode — AI plays, you observe

# Random agent (default)
jackdaw run --mode watch

# Greedy agent, slower speed so you can follow
jackdaw run --mode watch --agent greedy --speed 2.0

# Trained PPO model
jackdaw run --mode watch --agent ppo --model runs/balatro_ppo/balatro_ppo.zip

# Terminal only — no browser
jackdaw run --mode watch --no-web

# Specific seed so the run is reproducible
jackdaw run --mode watch --seed HELLO123

Play mode — you control everything

jackdaw run --mode play

The browser opens automatically at http://127.0.0.1:8765/?mode=play. The game waits at every decision point for you to click an action.

Stopping

After a game finishes, the terminal prints the result and says "press Ctrl+C to close". The browser dashboard stays open showing the final state. Press Ctrl+C to exit.

First time only: When the browser opens for the first time, press Ctrl+Shift+R to hard-reload and clear any cached files. After that, the server sends Cache-Control: no-cache headers so this is never needed again.

8. Training a PPO agent

Start training

# ~5 minutes on CPU (~80k steps)
python scripts/train_ppo.py --total-timesteps 80000

# Overnight run (more useful model)
python scripts/train_ppo.py --total-timesteps 2000000

The model saves to runs/balatro_ppo/balatro_ppo.zip when finished. If you press Ctrl+C during training, the model saves automatically before exiting.

Monitor training live

Open a second terminal while training runs:

tensorboard --logdir runs/balatro_ppo

Then open http://localhost:6006 in your browser. You'll see live charts of:

MetricWhat it means
mean_rounds_beatenAverage blinds cleared per game. Starts near 0, should rise as training progresses.
max_ante_reachedBest game so far. Ante 8 = winning the run.
win_rateFraction of games won. Stays 0 for a long time — winning requires beating all 8 antes.
ep_rew_meanAverage episode reward. Should gradually increase from negative toward positive.
explained_varianceHow well the value function predicts outcomes. Starts negative, should trend toward 1.0.

Watch the trained model play

jackdaw run --mode watch --agent ppo \
  --model runs/balatro_ppo/balatro_ppo.zip \
  --speed 1.5
Expectation: A model trained for only 80k steps will make poor decisions — it hasn't learned the game yet. Expect it to swap cards around or make random-looking choices. Useful behavior typically emerges after 500k–1M steps.

Continue training from a saved model

Edit scripts/train_ppo.py and change the model creation line:

# Instead of creating a new model:
model = MaskablePPO("MultiInputPolicy", env, ...)

# Load and continue from saved:
model = MaskablePPO.load("runs/balatro_ppo/balatro_ppo.zip", env=env)

9. Full CLI reference

jackdaw run [options]

Mode
  --mode         watch | play              (default: watch)

Agent (watch mode only)
  --agent        random | greedy | ppo     (default: random)
  --model        path/to/model.zip         (required when --agent ppo)

Game setup
  --deck         b_red | b_blue | b_ghost …  (default: b_red)
  --stake        1–8                        (difficulty, default: 1)
  --seed         any string                 (e.g. SEED42, default: random)

Watch mode speed
  --speed        seconds between steps      (default: 0.8)
                 0.2 = fast  |  2.0 = slow

Output toggles
  --no-terminal  disable Rich terminal output
  --no-web       disable browser dashboard

Web server
  --web-port     HTTP port                  (default: 8765, WS = port+1)

Examples

# Watch a random agent at high difficulty
jackdaw run --mode watch --stake 4 --agent random

# Play a game yourself
jackdaw run --mode play --deck b_blue --seed HELLO

# Watch PPO model, no terminal clutter
jackdaw run --mode watch --agent ppo \
  --model runs/balatro_ppo/balatro_ppo.zip \
  --no-terminal --speed 1.0

# Fast benchmark run (no display, terminal only)
jackdaw run --mode watch --no-web --speed 0 --agent greedy
